Failure Case Post-Mortems & Guardrails

Every failure case in NetSage AI was captured during human review, analyzed for hallucination causes, and mitigated through prompt refinements and deterministic rule checkers.

Architecture & Execution Workflow

Symptom, Rule Check, AI Diagnosis, Human Review, Fix

[1]

Deterministic Pre-Check (Independent Ground Truth)

Before invoking any AI, 8 modular deterministic rule checkers evaluate IP conflicts, subnet boundaries, gateway reachability, err-disabled interfaces, and routing table entries.

> python checker/rule_checker.py --all [PASS] Evaluated 32 cases | 29 violations flagged (90.6% detection)
[2]

Evidence-Grounded AI Inference

The prompt enforces strict JSON schema and mandates exact quotation of Cisco CLI parameters in the evidence field. Confidence is penalized if citations are omitted.

{ "root_cause": "OSPF interface MTU mismatch on link Gi0/0", "osi_layer": 3, "confidence": "high", "evidence": "R1 MTU is 1500 bytes vs R2 MTU is 1400 bytes", "next_command": "show ip ospf neighbor GigabitEthernet0/0" }
[3]

Mandatory Human-in-the-Loop Review

Every single diagnosis must be verified by a human network engineer. Reviewers record Accepted, Edited, or Rejected verdicts with technical rationale in review_log.csv.

▶ HUMAN REVIEW VERDICT: CASE-007: [REJECTED] - AI hallucinated MD5 key error, actual MTU mismatch. CASE-012: [REJECTED] - AI blamed ACL, actual NAT inside/outside inverted.
[4]

Continuous Feedback & Safeguards

Rejections and edits drive new deterministic rule plugins and prompt changelogs (v1.0 → v1.1 → v2.0) to prevent repeated hallucinations in production.
